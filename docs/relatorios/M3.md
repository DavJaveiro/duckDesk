# M3 — Modo simulador (janela 3D)

Branch: `m3-simulator`. Fecha a issue #4.

## O que foi implementado

| Peça | Arquivo | Notas |
|---|---|---|
| Câmera | `src/duckdesk/render/camera.py` | `CameraController` sobre `MjvCamera`: tracking de `trunk_base` por padrão (az 160° / el −20° / dist ~0,9 m); orbitar (arrasto esquerdo), pan (direito), zoom (roda), duplo-clique recentraliza, `C` alterna seguir/livre. Delega a matemática a `mjv_moveCamera` como o viewer nativo; arrastar durante o tracking cai para modo livre (comportamento do viewer). |
| Render offscreen | `src/duckdesk/render/offscreen.py` | `mujoco.Renderer` → frames RGB `np.ndarray` para o viewport Qt (ADR-0004; sem QOpenGLWidget). Câmera default interna p/ scripts, `MjvOption` exposto (contatos/juntas), `set_size` até 1920×1080; `SimCore` sobe `offwidth/offheight` do `MjSpec` p/ 1920×1080 (mudança em runtime, sem tocar no XML). |
| Janela | `src/duckdesk/ui/simulator_window.py` | `QMainWindow` "DuckDesk: Simulador", 1280×800: viewport `QImage` + eventos de mouse/teclado; painel Comportamentos (Sentar / Bicar / Cambalhota / Chutar esq/dir / Reset + 4 sliders de cabeça + 6 de corpo); status bar (política, vx/vy/wz comandado→medido, fps de render, passos atrasados); menus Arquivo / Simulação / Comportamentos / Visualização / Modo / Ajuda. |
| Laço/app | `src/duckdesk/app.py` | `AppController`: `QTimer` 8 ms `Qt.PreciseTimer` na thread do Qt (ADR-0003), `SimClock` executa 0–5 passos de controle/tick; render com cap de 60 fps; teclado integrado via `KeyboardMapper` (WASD/QE/Shift/Y/G/R/K/L/Espaço/Backspace/P/Ctrl+M); empurrão 2 N lateral × 0,1 s em `xfrc_applied` com limpeza automática; bandeja mínima (menu completo no M4); fechar esconde, "Sair" encerra. |
| Settings | `src/duckdesk/settings.py` | `%APPDATA%\DuckDesk\settings.json`: geometria da janela e velocidade; tolerante a arquivo ausente/corrompido. |
| Demo | `scripts/record_demo.py` | Offscreen: instancia o `AppController` real e captura `window.grab()` para MP4. |

## Critérios de aceite

1. **Vídeo 60–90 s**: `docs/relatorios/midia/m3_demo.mp4` (1280×800, ~76 s, 12 fps) — marcha, giro, passo lateral, sentar/levantar, bicar, cambalhota, chute esq/dir, empurrão+recuperação, sliders de cabeça/corpo; janela real com painel, menus e status bar.
2. **ONNX inválido**: `test_invalid_onnx_warns_in_pt` — arquivo inválido gerado no teste → aviso em pt-BR, sem crash, política oficial preservada; `test_valid_onnx_swaps_walk` — `velstand.onnx` carrega pelo fluxo do menu, `active == "walk"`. A carga chama `validate_user_onnx`, troca só o papel `walk` e faz reset.
3. **Ciclo de vida**: `test_close_hides_with_tray` (fechar → evento ignorado + janela escondida), `test_close_quits_without_tray` (sem bandeja → aceita), `test_quit_stops_timer` (Sair → timer parado + quit). `quitOnLastWindowClosed=False` com bandeja ativa.
4. **FPS/CPU @1280×800**: 842 frames em 20 s → **42 fps** no viewport 1087×746; CPU ≈ **2,4 núcleos** (inclui intra-op do ONNX Runtime). Render ~6 ms, passo de controle ~0,5 ms — o restante é conversão `QImage` + execução Qt; não há threads extras (ADR-0003).

## Desvios / dúvidas

- "Enviar para a barra de tarefas" existe **desabilitado** (Ctrl+M mostra "modo mascote chega no M5"), conforme spec M5.
- Bandeja mínima neste marco (menu completo no M4); já sustenta "esconder ao fechar, encerrar no Sair".
- O fps real é medido na UI (≈42 fps), não o cap teórico de 60.
- O vídeo usa captura offscreen do `AppController` real (mesmo pipeline de render/teclado da janela).
